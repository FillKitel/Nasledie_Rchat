# Архитектура продукта

## Этап 1 — продуктовый прототип

Текущий клиент позволяет быстро проверять навигацию, внешний вид и будущие функции
на desktop и мобильном экране. Данные в большинстве разделов пока демонстрационные
и сохраняются локально.

В v0.3 добавлен первый локальный realtime-контур: сервер принимает сообщения,
сохраняет короткую историю и рассылает новые события открытым web-клиентам. В
v0.4 добавлено QR-подключение телефона к Mac-серверу в той же Wi‑Fi сети. Это не
production-backend, а проверка главного механизма мессенджера: сообщение из
одного клиента появляется в другом без перезагрузки.

В v0.5 добавлен первый слой Identity на клиенте: локальный профиль, username,
название устройства и постоянный device ID в браузере. Это ещё не облачная
регистрация, но уже убирает состояние «безличного устройства» и готовит основу
для аккаунтов, доверенных устройств и синхронизации.

В v0.6 добавлен первый слой Presence: сервер видит открытые локальные клиенты,
группирует подключения по device ID и рассылает список устройств онлайн в
локальную комнату через SSE.

В v0.7 добавлен первый слой Conversations поверх локального сервера: из участника
локальной комнаты можно открыть личный диалог, а сообщения маршрутизируются по
отдельному `chatId`, не смешиваясь с общей комнатой `live`.

## Этап 2 — единый нативный клиент

Для приложений App Store, Google Play и macOS планируется Flutter-клиент. Он даст
общий слой интерфейса и бизнес-логики для iOS, Android, macOS и при необходимости
Windows/web. Прототип служит визуальной спецификацией для этого клиента.

## Этап 3 — сервер

Предлагаемый первый серверный контур:

- API и realtime-шлюз: TypeScript + WebSocket;
- основная база: PostgreSQL;
- быстрые состояния и очереди: Redis;
- файлы: S3-совместимое хранилище;
- push-уведомления: APNs и Firebase Cloud Messaging;
- авторизация: номер телефона или email, одноразовый код, сессии устройств.

## Границы модулей

1. Identity — пользователи, профили, устройства и сессии.
2. Conversations — личные диалоги, группы, роли и участники.
3. Messaging — сообщения, ответы, реакции, редактирование и удаление.
4. Realtime — доставка событий, статусы online и «печатает».
5. Media — загрузка, обработка и выдача изображений, видео и файлов.
6. Notifications — push и настройки уведомлений.
7. Calls — отдельный WebRTC-контур; добавляется после стабильного обмена сообщениями.

## Локальный realtime v0.7

- `server/index.js` — dependency-free Node.js сервер;
- `GET /api/health` — проверка доступности и текущие участники;
- `GET /api/connect` — LAN-ссылка и подсказки для подключения телефона;
- `GET /api/connect.svg` — QR-код для открытия web/PWA на iPhone или Android;
- `GET /api/messages?chatId=live` — история локального живого чата;
- `GET /api/messages?chatId=dm-...` — история личного локального диалога;
- `GET /api/presence` — устройства и подключения онлайн;
- `POST /api/messages` — отправка сообщения с локальным профилем автора и нужным `chatId`;
- `GET /api/events` — Server-Sent Events поток для сообщений и presence;
- `server/.data/messages.json` — локальная история, не коммитится в репозиторий.

## Безопасность

На MVP транспорт защищается TLS, секреты хранятся вне репозитория, сервер проверяет
доступ к каждому диалогу. Сквозное шифрование нельзя «прикрутить потом» одной
галочкой: для секретных диалогов оно проектируется отдельным протоколом с управлением
ключами, сменой устройств и резервным восстановлением.
