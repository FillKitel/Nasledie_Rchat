# Nasledie RChat

Новая кроссплатформенная версия мессенджера команды. Рабочее название интерфейса
пока — «Маяк»; бренд можно заменить без переделки архитектуры.

Сейчас в репозитории есть web-прототип (PWA), который адаптируется под desktop,
macOS, iPhone и Android, плюс первый локальный realtime-сервер для живой проверки
сообщений между двумя окнами. В v0.5 добавлен первый вход: локальный профиль
пользователя, username и имя устройства. В v0.6 локальная комната показывает
устройства онлайн. В v0.7 из участника комнаты можно открыть личный локальный
чат, который тоже проходит через сервер. В v0.8 появились постоянные аккаунты,
пароли, сессии устройств и серверная проверка доступа к диалогам. В v0.9 добавлена
поддержка интернет-сервера с PostgreSQL, регистрацией по приглашению и HTTPS.
Параллельно создаётся Flutter-клиент
для настоящих приложений iOS, Android и macOS.

## Быстрый запуск

Для живого режима нужен Node.js 22.16+ (рекомендуется 24). Если `node` или `flutter`
не находятся в `PATH`, укажите пути к ним в `.env.local` по образцу `.env.example`.
Локальные настройки и база с переписками не публикуются в Git.

```sh
npx --yes pnpm@11.19.0 install --frozen-lockfile
./script/run_local_chat.sh
```

После этого откройте `http://127.0.0.1:4173`, перейдите в диалог «Живой чат» и
нажмите «Локальная комната». Там появится QR-код и LAN-ссылка вида
`http://192.168.x.x:4173`. Если открыть эту ссылку на iPhone или Android в той же
Wi‑Fi сети, диалог «Живой чат» будет получать сообщения через локальный сервер.
При первом открытии «Маяк» попросит зарегистрировать аккаунт по username и паролю.
На телефоне выберите «Вход» и используйте те же данные: сервер создаст отдельную
сессию устройства и синхронизирует доступные локальные диалоги.

На iPhone можно открыть ссылку в Safari, нажать «Поделиться» → «На экран Домой»
и получить PWA-иконку «Маяк» без App Store/TestFlight.

Статический режим без сервера всё ещё можно открыть так:

```sh
python3 -m http.server 4173 --directory app
```

Но в нём «Живой чат» останется без realtime-доставки.

## Интернет-сервер v0.9

Инструкция для бесплатного пилота на Render + Neon: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
Пользователи подключаются по одной HTTPS-ссылке из разных сетей; Mac можно выключать.
Локальная SQLite-база остаётся на Mac. В облаке нужна отдельная PostgreSQL-база:
файловая система бесплатного Render не подходит для хранения переписок.

Это тестовая версия, не готовая замена защищённому промышленному мессенджеру.
Сквозного шифрования, восстановления пароля и звонков пока нет.
Администратор базы технически может прочитать сообщения. HTTPS защищает транспорт.
При первом запуске в списке только «Живой чат» и пустые «Сохранённые».
Старые демонстрационные контакты удаляются из локального кэша при обновлении;
реальные диалоги и пользовательские заметки сохраняются. «Сохранённые» пока
хранятся только в текущем браузере, без серверной синхронизации.

## Проверки

```sh
npx --yes pnpm@11.19.0 run check
npx --yes pnpm@11.19.0 test
```

Локально тесты используют временные SQLite и PostgreSQL-совместимый PGlite через TCP.
GitHub Actions дополнительно запускает те же проверки на отдельном PostgreSQL 17.
Пользовательские базы в тестах не используются.

## Что уже работает

- адаптивный интерфейс для большого и маленького экрана;
- список и поиск диалогов;
- поиск зарегистрированных пользователей по имени и @username через «Люди» или «Новый диалог», включая офлайн-получателей;
- переключение между чатами;
- отправка сообщений с локальным сохранением;
- удаление своих сообщений у всех участников;
- персональная очистка истории чата на всех устройствах аккаунта;
- регистрация и вход по username и паролю;
- отдельные серверные сессии устройств;
- настройка имени, описания профиля и аватара;
- статус пользователя «в сети» и время последнего посещения;
- счётчик непрочитанных и отметка прочтения в личных диалогах;
- Web Push-уведомления о новых личных сообщениях;
- SQLite локально или PostgreSQL в облаке;
- код приглашения для регистрации в интернет-пилоте;
- ограничения запросов и проверка источника изменяющих запросов;
- ручной экспорт/восстановление данных между SQLite и PostgreSQL;
- проверка участия пользователя перед чтением и отправкой сообщений;
- список устройств онлайн в локальной комнате;
- личный локальный чат с участником комнаты;
- светлая и тёмная темы;
- PWA-манифест и offline-кэш приложения;
- локальный realtime-сервер;
- живой диалог между двумя клиентами через HTTP + Server-Sent Events;
- QR-подключение телефона к локальному серверу.

Уведомления включаются пользователем в настройках профиля. На iPhone Web Push
работает для установленного на экран «Домой» приложения; на Mac и Android — в
поддерживаемых браузерах после выдачи разрешения. Уведомления зависят от системных
настроек и доступности push-службы браузера.

## Структура

- `app/` — запускаемый клиентский прототип;
- `server/` — локальный и облачный realtime-сервер v0.9;
- `render.yaml` — бесплатный web-сервис (база Neon настраивается отдельно);
- `clients/rchat_app/` — единый Flutter-клиент (добавляется);
- `docs/ARCHITECTURE.md` — план перехода к полноценному продукту;
- `docs/LEGACY_AUDIT.md` — что наследуем из старого RChat;
- `outputs/` — пользовательские сборки и демонстрационные материалы.
